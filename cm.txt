feat: finish an emailed verification code without a person at the browser

Greenhouse increasingly refuses a submission until an emailed one-time code
is typed back. Naming that gate stopped the misleading failure report, but
every affected application still needed someone sitting in front of an
assisted window: Stripe, Okta, Tailscale and Discord all stop here.

submit_application now takes verificationCode and completes the gate.

The code box is rendered as one input per character, so a fill() into any
single box delivers one character and silently leaves the rest blank. The
segmented path is tried first and requires exactly as many visible boxes as
the code has characters, then reads each box back, so a partial code is
never submitted as though it were complete. A single-box layout still works
through the original selectors.

A refused code is now said plainly, including that a new one has been
emailed - the remedy is a fresh code, not another attempt at the old one.
